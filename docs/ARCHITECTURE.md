# Состояние реализации

Актуальное описание возможностей и API — в [README.md](README.md).

## Что переделано в этой итерации

### Аккаунты и авторизация

- Таблица `users`: Argon2-хэш пароля, обратимо зашифрованный пароль для проверки
  Subsonic-токена, отображаемое имя, роль, API-ключ, Last.fm/ListenBrainz-поля.
- Сессии в БД + HttpOnly-cookie `rustream_session` (30 дней).
- При первом запуске создаётся `admin` / `admin`; пароль можно задать
  `RUSTREAM_ADMIN_PASSWORD`.
- Администратор создаёт и удаляет пользователей через **Аккаунт → Пользователи**.
- Subsonic-авторизация: `p` (plain/`enc:`), `t`+`s`, `apiKey`, HTTP Basic и
  браузерная cookie.

### Персональные данные

- `stars` перестроена с `(item_id,item_type)` на `(user_id,item_id,item_type)`.
- `playlists.user_id`; плейлисты фильтруются и проверяются по владельцу.
- `plays`: история, позиция, завершённость, флаг отправки скроббла.
- `/api/me`, `/api/me/stats`, `/api/me/scrobbling`, `/api/me/history`,
  `/api/plays/start`, `/api/plays/update`.
- Старые избранные и плейлисты мигрируют на администратора.

### Скробблинг

- Last.fm: получение токена, `auth.getSession`, `track.scrobble`.
- ListenBrainz: `submit-listens` по пользовательскому токену.
- Скроббл отправляется после половины трека или 4 минут; повторно не дублируется.
- Настройки — в меню аккаунта; ключи Last.fm приложения — в `config.toml`.

### Live и миксы

- `/api/live/queue` — персональная очередь с весами: избранное, любимые артисты,
  штраф за недавние треки, немного случайности.
- `/api/live/mixes` — «Избранное», «Новинки», «Часто играет».
- Плеер при окончании Live-очереди сам запрашивает следующую партию.
- Страница **Live** с эфиром, миксами и историей.

### Сканер

- Период сканирования `scan_interval_secs` (по умолчанию 300).
- Файловый watcher (`notify`) с дебаунсом 4 секунды — реакция на торрент-загрузки.
- Блокировка одновременных сканов.
- Защита от затирания библиотеки, если музыкальная папка не смонтирована.
- Чистка осиротевших избранных после пересканирования.

### Subsonic-совместимость

- Маршруты с `.view` и без него, GET/POST/HEAD.
- Редирект при двойном `/rest/rest/...`.
- XML по умолчанию, JSON при `f=json`, POST-формы нормализуются в query.
- `stream` и `download` отдают файл напрямую, без редиректа (иначе клиенты теряют
  авторизацию); Range сохранён.
- `getUser` возвращает реального пользователя, плейлисты/избранное — его данные.

### Тексты и UI

- LRCLIB + резервный lyrics.ovh, кэш, источник и кнопка повторного поиска.
- Новый экран входа, меню аккаунта, настройки скробблинга и пользователей.
- Главная показывает личную статистику вместо общей карточки библиотеки.
- Адаптивная навигация с Live, мобильные экраны и меню настроек.

### Оценки, темы и состояние плеера

- Таблица `dislikes` (`user_id`, `item_id`, `item_type`); лайки остаются в `stars`.
  Лайк и дизлайк взаимоисключающие, оба доступны из строки трека, плеера и
  полноэкранной панели. `setRating` в Subsonic API тоже обновляет оценки.
- Live-очередь и миксы исключают дизлайкнутые треки.
- Статистика пользователя расширена: `likes`, `dislikes`, `byDay` (14 дней) и
  `topGenres`; недавние треки сохраняют порядок прослушивания.
- Тема оформления хранится в `users.theme` (violet/ocean/sunset/forest/mono) и
  применяется при входе на любом устройстве.
- Очередь, позиция, режим Live и пауза сохраняются в `localStorage` и
  восстанавливаются после перезагрузки; автозапуск звука ждёт клика.
- Сессия — 90 дней, скользящее продление при активности.
- Админ может сохранить `lastfm_api_key`/`lastfm_api_secret` из веб-интерфейса;
  сервер аккуратно переписывает эти ключи в `config.toml` и обновляет конфиг
  в памяти без рестарта.

## Ограничения

- YouTube Music не подключён: нужен `yt-dlp` и, вероятно, cookies.
- Транскодирования нет.
- CUE с несколькими `FILE` — треклист, а не образ.
- Открытая регистрация выключена по умолчанию.
