# Rustream UI — дизайн-система

## Направление

«Тихая аппаратура»: интерфейс не соревнуется с обложками. Нейтральный графит,
одна тёплая акцентная пара (латунь), плотные списки как в hi-fi компоненте.
Никаких градиентов на тексте и кнопках, никаких blur-«стёкол» и фоновых пятен.

Светлая тема — `html.light-mode`: тёплая бумага `#faf8f4`, акцент `#74560f`.
Темы (`body[data-theme]`) меняют только акцент; для светлой темы у каждой темы
есть отдельный тёмный вариант акцента — иначе получался светлый текст на
светлой кнопке.

## Типографика

Системный стек (`ui-sans-serif` / `-apple-system` / `Segoe UI` / `Roboto`) —
внешних шрифтов нет, ноль сетевых запросов.

| Роль | Размер / вес |
|---|---|
| h1 | `clamp(26px, 2.6vw, 34px)` / 600 / `-0.025em` |
| h2 | 18px / 600 |
| body | 14px / 400 |
| label | 12–13px / 500 |
| rail label | 11px / 500 |

Цифры (длительности, счётчики, даты) — `font-variant-numeric: tabular-nums`.

## Формы

`4 / 8 / 12 / 16 / 28px`. Кнопки и поля поиска — pill (`999px`), карточки —
`12px`, обложки в списках — `8px`, листы — `28px`.

Мобильный плеер: прогресс — 3px-линия сверху, ниже обложка 44px, название и
только prev/play/next. Ничего не перекрывает таббар: все блоки — flex-дети
`#app`, `overflow: hidden` исключает наложение.

## Состояния

- hover — только там, где есть курсор (`@media (hover: none)` показывает
  вторичные действия сразу);
- focus-visible — 2px контур `--primary`;
- `prefers-reduced-motion` отключает анимации;
- пустые состояния объясняют, что сделать, а не «пусто».

## Проверка

Скриншоты через Camoufox MCP на `https://music.gameusit.ru`:
десктоп 1440×900 и телефон 390×844 — главная, альбом, треки, статистика,
профиль, светлая тема, полноэкранный плеер, очередь.

## Дополнения (вторая итерация)

- **Источник в ленте**: треки YouTube помечаются `YT` (secondary-container),
  локальные — форматом (FLAC/MP3). Главная смешивает сервер и YouTube.
- **YouTube-главная**: история из локальной БД (`/api/ytm/history`), лайки,
  быстрые подборки-чипы и поиск. Пустой экран остаётся только для
  неподключённого профиля.
- **Плотность**: `html[data-density="compact|default|large"]` меняет высоты
  топбара/плеера/рейла, плотность списков и размер сетки обложек.
- **Свой цвет**: один выбранный hex разворачивается в палитру — поверхности
  подкрашиваются, `on-primary` и `on-primary-container` считаются по
  относительной яркости WCAG, поэтому текст на кнопках не сливается.
- **Громкость**: трек 4px цвета `outline`, ползунок виден всегда (14px),
  увеличивается при перетаскивании.

## URL-контракт (deep-link)

Hash — единственный источник истины: любой экран открывается по ссылке, переживает
F5, копирование и back/forward.

| Маршрут | Экран |
|---|---|
| `#/home` | Главная |
| `#/live` | Live-очередь |
| `#/stats` | Статистика |
| `#/search?q=…` | Поиск |
| `#/library/playlists\|albums\|artists\|tracks\|favorites\|recent` | Медиатека |
| `#/album/:id`, `#/artist/:id`, `#/playlist/:id` | Детальные страницы |
| `#/ytm/search\|liked\|history\|connect` | YouTube Music |
| `#/profile` | Профиль |
| `?player=lyrics\|queue\|info\|eq` | Плеер открыт на вкладке |

- Старый вид `#/library?tab=x` редиректит на `#/library/x`.
- `?player=` добавляется `pushState` при первом открытии, при закрытии плеера
  убирается `replaceState`; переключение вкладок не плодит записи истории.
- Позиция скролла запоминается по hash и восстанавливается при back/forward.
- `#/ytm` доступен из сайдбара (десктоп) и иконкой в топбаре (телефон).

## Плеер

Полноэкранный лист: обложка и мета слева/сверху, справа/снизу — карусель из
четырёх страниц (Текст / Очередь / Инфо / Звук). Страницы не перерисовываются при
переключении: лента сдвигается по `--np-page`, свайп влево/вправо меняет страницу.
На телефоне вкладки — нижняя панель над транспортом. Обложка не «схлопывается»:
альбом и чипы формата перенесены в «Инфо», чтобы тексту оставалось место.

## Текст: пословная синхронизация

Enhanced-LRC (`<mm:ss.xx>слово`) парсится в `SyncedLine.words[]` (`start_ms`,
`end_ms`, `text`). Конец слова вычисляется по следующему слову или следующей
строке. Если файл обычный (построчный) LRC, слова разносятся по длительности
строки пропорционально их длине — караоке подсвечивает слово, а не прыгает по
строкам; группа из нескольких слов под одним тегом делится так же. В UI
текущее слово красится акцентом, предыдущие — `on-surface`, будущие —
`on-surface-faint`. Кэш лирики (`lyrics_cache.synced`) хранит слова вместе со
строками; старые записи без `words` досчитываются при чтении из кэша.

Трек YouTube Music тоже получает текст: метаданные берутся из `ytm_tracks`
(или из совпавшего локального файла, чтобы подхватить соседний `.lrc`), кэш
ключуется по `ytm-<video>`.

Найденный текст сохраняется на диск: сначала рядом с аудиофайлом
(`<файл>.lrc`, enhanced-LRC с пословными метками), а если библиотека
read-only — в каталоге сервера рядом с базой (`<db>/lyrics/<файл>-<hash>.lrc`).
Сохранённый текст читается до сети, поэтому панель открывается мгновенно и
работает, когда сервис текстов недоступен. Кнопка «Найти заново» игнорирует и
sidecar, и кэш, а «Искать в интернете» — только кэш. Ответ «текста нет»
помнится час, чтобы панель не опрашивала сервисы на каждом открытии.

Провайдеры опрашиваются параллельно: LRCLIB (пословная синхронизация) и
lyrics.ovh (простой текст). LRCLIB спрашивается через `/api/get` с длительностью
трека (одна запись, быстрый ответ) и только затем через `/api/search`;
запросы идут с паузой и с `User-Agent`, иначе сервис отвечает `429`.
Ответы различаются: «текста нет» (сервис ответил, записи нет) и «сервис
недоступен» (лимит запросов, сбой, таймаут). Только первый попадает в
негативный кэш — при недоступности сервиса текст может появиться позже.
Панель в этом случае показывает «Сервис текстов недоступен» и кнопку повтора,
а не «Текст не найден».

## Источник звука: локальный файл важнее YouTube

`ytm::local_match` ищет трек в локальной библиотеке по нормализованным
названию и артисту плюс длительности (±8 с). Если файл найден, `serve_stream`
отдаёт его напрямую (обычно FLAC) и не запускает `yt-dlp`; в списках YouTube
такой трек помечается реальными `suffix`/`bitRate` и `localId`.

## Экономия трафика

`users.data_saver` (0/1), `PUT/PATCH /api/me` с `{dataSaver}`. Включает запрос
самого низкого битрейта YouTube (~48–64 kbps) и участвует в ключе кэша
разрешённых URL (`ytm_tracks.resolved_saver`), поэтому переключение режима не
переиспользует чужой URL. Локальные файлы режим не затрагивает.

## Ползунки и чипы качества

Ползунок громкости (нижняя панель и лист «Сейчас играет») рисуется как
заполненная шкала: акцентом до текущего значения, `outline` — после. Без
заливки на тёмной теме оставался только кружок, непонятно, где ноль.

«lossless» — свойство формата, а не заглушка при отсутствии битрейта. Чип
`lossless` показывается только для flac/wav/alac/ape/aiff/dsf/dff; иначе —
`N kbps`; если неизвестно ничего (трек YouTube до разрешения), второй чип не
рисуется вовсе. Формат всегда показывается реальным (`FLAC`, `M4A`), у трека
YouTube Music с локальным совпадением — `FLAC` и `lossless`.

Колесо мыши над ползунком громкости (нижняя панель и лист «Сейчас играет»)
меняет громкость шагом 4% и не скроллит страницу.

## Каркас: сайдбар по Feishin

Визуальный язык взят по референсам Feishin (дизайн, не код — проект под GPL-3.0).

- Сайдбар 240px от 1200px, пункты — строкой: иконка 19px + подпись 13px,
  высота строки 40px. Сверху группа «Моя библиотека» (Главная, Избранное,
  Альбомы, Треки, Артисты, Плейлисты), ниже группа «Онлайн» (YouTube Music,
  Live), внизу — Статистика, Профиль, горячие клавиши. Заголовки групп —
  капсом 11px, `on-surface-faint`.
- Заголовок страницы: крупная круглая play-кнопка 52px слева (акцент
  `primary`, тень вниз), затем название с чипом-счётчиком и подзаголовок.
  Кнопка появляется только там, где есть что играть (`play` в `pageHeader`).
- Главная: hero-баннер с размытым фоном из обложки, ниже «Жанры» пилюлями с
  цветной полосой 5px слева (цвет детерминирован от позиции, `nth-child(6n)`),
  ниже сетка «Из вашей библиотеки» из `albumCard()`.
- Нижний бар: слева обложка + название/артист, по центру транспорт с
  прогрессом, справа громкость и качество.
- Телефон: нижняя таб-панель Главная / Поиск / Медиатека / YouTube / Профиль,
  мини-плеер над ней, `overflow-x: clip` на `html`/`body` — страница не ездит
  вбок, длинные подписи обрезаются внутри своих контейнеров.

## Рельс и плотность

На экранах от 1200px левый рельс всегда 240px с подписями, независимо от
пресета плотности. Объявлять ширину нужно на `:root`: селектор `html`
(0,0,1) проигрывает `:root` (0,1,0) из блока токенов, и рельс оставался 88px.
Плотность влияет на вертикальные размеры (строки, отступы, шапка), но не на
ширину рельса.

## Настройки

Диалог «Аккаунт и настройки» — двухпанельный: слева список разделов
(Профиль, Оформление, Воспроизведение, Скробблинг, Безопасность, Библиотека,
Пользователи — только админу, О сервисе), справа содержимое выбранного
раздела. Активный раздел запоминается на время сессии. Ширина 900px на
десктопе, на телефоне — нижний лист с горизонтальной прокруткой разделов.

Заголовок и содержимое живут в одной карточке (`.modal-card`): раньше
заголовок висел отдельно над карточкой и на телефоне наезжал на страницу.
Закрытие — крестик, клик по затемнённой области или Esc.

Скробблинг показывает состояние каждого сервиса (точка + «подключён»),
позволяет сохранить токен и отключить сервис (`DELETE /api/me/scrobbling`).
В «Безопасности» — смена пароля, Subsonic API (адрес, логин, ключ с кнопкой
копирования) и выход. В «Оформлении» — режим (тёмная/светлая/системная),
акцент и плотность; в «Воспроизведении» — экономия трафика.
