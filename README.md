# Rustream — музыкальный сервер

Лёгкий музыкальный сервер на Rust: локальная библиотека, веб-интерфейс в стиле
Liquid Glass, OpenSubsonic API для мобильных клиентов, сырой FLAC-стриминг с
Range-запросами, 10-полосный эквалайзер, тексты песен, персональный Live-поток и
YouTube Music, привязанный к каждому профилю отдельно.

## Возможности

- **Библиотека**: FLAC, MP3, M4A, AAC, OGG/Opus, WAV, AIFF; вложенные обложки и
  `cover.jpg`/`folder.*`; CUE-образы с виртуальными треками.
- **Автообновление**: период сканирования настраивается, плюс файловый watcher —
  новые файлы от торрент-клиента появляются через несколько секунд. Если музыкальная
  папка не смонтирована, существующая библиотека не затирается.
- **Метаданные**: артист определяется по корневой папке (`/music/Артист/Альбом/…`),
  поэтому разные написания в тегах не дробят исполнителя; счётчики альбомов и
  треков, длительность, год, жанр, битрейт, формат.
- **Аккаунты**: логин/пароль, несколько пользователей, роли администратора,
  отдельные избранные треки, плейлисты, история и статистика у каждого.
  Сессия живёт 90 дней и продлевается автоматически при активности.
- **Регистрация по приглашению**: администратор выдаёт код (срок, число
  использований, права), человек сам выбирает логин и пароль.
- **YouTube Music на профиль**: каждый вставляет свои cookies (Cookie-Editor),
  сервер хранит их зашифрованными и использует только для этого пользователя.
  Поиск, лайки и воспроизведение идут через InnerTube и `yt-dlp`, аудио
  кэшируется на диск с вытеснением старых файлов.
- **Оценки**: лайк и дизлайк у каждого трека; дизлайки исключаются из Live,
  миксов и рекомендаций.
- **Скробблинг**: локальная история + Last.fm и ListenBrainz. Ключи приложения
  Last.fm можно сохранить прямо в настройках — они пишутся в `config.toml`.
- **Live**: персональный поток из избранного, любимых артистов и редких треков,
  автоматически добирает очередь. Плюс готовые миксы «Избранное», «Новинки»,
  «Часто играет».
- **Веб-интерфейс**: Liquid Glass, адаптирован под телефон (нижняя навигация),
  главная, каталог, поиск, YouTube Music, профиль, плейлисты, избранное, очередь,
  полноэкранный плеер.
- **Плеер**: буфер в секундах/мегабайтах, формат/битрейт/размер, seek,
  shuffle/repeat, медиа-клавиши, 10-полосный эквалайзер, синхронизированные тексты.
  Очередь, позиция трека и режим Live переживают перезагрузку страницы.
- **API**: Subsonic 1.16.1 в JSON (`f=json`) и XML (по умолчанию), с авторизацией
  по паролю, Subsonic-токену, API-ключу и HTTP Basic.
- **Стриминг**: без перекодирования (raw), HTTP Range, потоковая отдача;
  CUE-сегменты через ffmpeg.

## Быстрый старт

```bash
cargo build --release
./target/release/rustream
```

Или через Docker:

Многоступенчатый `Dockerfile` собирает и веб-интерфейс, и musl-бинарник:

```bash
docker build -t rustream:latest .
docker run -d -p 4533:4533 \
  -v /path/to/music:/music:ro \
  -v rustream-data:/data \
  rustream:latest
```

В образе уже есть `ffmpeg` и `yt-dlp`. Готовый `docker-compose.yml` делает то же
самое: `docker compose up -d --build`.

При первом запуске создаётся администратор **admin / admin**. Сразу смените пароль
в меню аккаунта. Пароль можно задать заранее переменной окружения
`RUSTREAM_ADMIN_PASSWORD`.

## Конфигурация

`config.toml` рядом с бинарником (или `WorkingDirectory` сервиса):

```toml
music_dirs = ["/music"]
bind_addr = "0.0.0.0:4533"
db_path = "/var/lib/rustream/rustream.db"
static_dir = "static"
online_lyrics = true
scan_interval_secs = 300

# YouTube Music: каждый пользователь подключает свои cookies в профиле
ytm_enabled = true
ytdlp_path = "yt-dlp"
ytm_cache_dir = "cache/ytm"
ytm_cache_max_mb = 1024

# Для кнопки «Подключить Last.fm» (необязательно)
# lastfm_api_key = "..."
# lastfm_api_secret = "..."
```

Ключи Last.fm может сохранить администратор прямо в веб-интерфейсе
(**Аккаунт → Скробблинг**): они записываются в `config.toml` и применяются без
перезапуска. Без ключей можно вставить готовый `session key` вручную.
ListenBrainz работает по токену из `https://listenbrainz.org/settings`.

## Аккаунты и статистика

- Новый пользователь появляется двумя способами: администратор создаёт его в
  **Профиль → Настройки → Пользователи**, либо выдаёт приглашение
  (**Профиль → Приглашения**). По ссылке `#/register?invite=…` человек сам задаёт
  логин и пароль; код можно ограничить сроком, числом регистраций и правами.
- У каждого пользователя свои избранные треки, дизлайки, плейлисты, история,
  статистика, тема оформления и ключ Subsonic API.
- История пишется при старте трека и обновляется при достижении половины/4 минут;
  в этот момент отправляется скроббл в Last.fm и/или ListenBrainz.
- **Статистика** — отдельная вкладка: часы, прослушивания, лайки/дизлайки,
  график за 14 дней, жанры, артисты, топ треков и недавняя история.
- **Live** учитывает избранное, историю и любимых артистов, избегает повторов и
  полностью исключает дизлайкнутые треки.

## Веб-интерфейс

Откройте `http://<сервер>:4533/`.

- **Главная** — быстрый старт музыки, кликабельные обложки последних альбомов,
  «продолжить слушать» после перезагрузки, недавние альбомы и артисты.
- **Live** — персональный эфир и готовые миксы.
- **Статистика** — личные часы, график, жанры, артисты, топ треков, лайки и дизлайки.
- **Артисты / Альбомы / Треки** — каталог с обложками.
- **Плейлисты** — создание, добавление треков, удаление.
- **Избранное** — сердечко у трека.
- **Поиск** — `Ctrl+K` или поле сверху; результаты YouTube Music попадают и в
  поиск Subsonic, поэтому мобильные клиенты видят их без отдельной настройки.
- **YouTube Music** — поиск и «Мои лайки» для подключённого профиля.
- **Профиль** — кнопка в шапке: подключение YouTube Music, тема, приглашения
  (для админа), настройки и выход.
- **Плеер** — клик по обложке или «Сейчас играет» открывает панель с текстом,
  эквалайзером и очередью.
- **Аккаунт** — имя, тема оформления (5 палитр), пароль, скробблинг, ключи
  Last.fm (для админа), пользователи (для админа), Subsonic-ключ.

### Тексты песен

Порядок поиска:

1. Файл `.lrc` или `.txt` с тем же именем, что и трек, рядом с аудиофайлом.
2. Кэш ранее найденных текстов.
3. [LRCLIB](https://lrclib.net), затем [lyrics.ovh](https://lyrics.ovh)
   (если `online_lyrics = true`).

В панели текста виден источник и кнопка повторного поиска.

### Эквалайзер

10 полос: 32, 64, 125, 250, 500 Гц, 1, 2, 4, 8, 16 кГц, диапазон ±12 дБ.
Пресеты: Ровно, Рок, Поп, Джаз, Бас, Вокал, Электроника. Настройки хранятся в
`localStorage` браузера. Обработка идёт через Web Audio API.

## Мобильные клиенты (Subsonic)

- **Тип сервера:** Subsonic
- **URL:** `http://<сервер>:4533` — без `/rest` на конце
- **Логин/пароль:** учётная запись Rustream (по умолчанию `admin` / `admin`)
- Можно использовать `u` + `apiKey` вместо пароля; ключ показан в настройках.

Клиенты:

- **Symfonium** (Android, платный, очень хороший)
- **Tempo** / **play:Sub** / **Amperfy** (iOS)
- **DSub** (Android, бесплатный)
- **Feishin** и **Sonixd** (desktop, Linux/Windows/macOS)
- **Airsonic**-совместимые клиенты

Если клиент даёт 404, проверьте, что в URL нет `/rest` и нет лишнего слэша.
Сервер принимает и `/rest/ping.view`, и `/rest/ping`, GET и POST, JSON и XML,
пароль, токен и HTTP Basic.

Поддерживаются методы:

```
ping, getLicense, getUser, getMusicFolders
getIndexes, getArtists, getArtist, getArtistInfo, getArtistInfo2
getMusicDirectory, getAlbum, getAlbumInfo, getAlbumInfo2
getAlbumList, getAlbumList2, getRandomSongs
getSong, search2, search3, getTopSongs, getSimilarSongs2
stream, download, getCoverArt, getLyrics
getPlaylists, getPlaylist, createPlaylist, updatePlaylist, deletePlaylist
star, unstar, getStarred, getStarred2, setRating, scrobble
getGenres, getScanStatus, startScan, getOpenSubsonicExtensions
```

## Развёртывание на Proxmox LXC

```bash
cp deploy/.env.example deploy/.env   # DEPLOY_SSH, LXC_ID, RUSTREAM_DIR, HOST_URL
./deploy/deploy.sh
```

Скрипт собирает образ (UI + musl-бинарник), копирует бинарник и статику в
контейнер, делает сжатую резервную копию базы (`/opt/rustream/backups`),
доустанавливает `yt-dlp` в `/opt/rustream/bin`, запускает `rustream.service` и
проверяет API. Музыка не затрагивается.

Ручное управление:

```bash
ssh pve 'pct exec 104 -- systemctl status rustream'
ssh pve 'pct exec 104 -- journalctl -u rustream -f'
ssh pve 'pct exec 104 -- systemctl restart rustream'
```

## Сборка веб-интерфейса

```bash
cd rustream-ui
npm install
npm run build      # результат в ../static
```

Vite собирает в `static/`, `base` — `/static/`. Сервер отдаёт эту папку по
`/static`, а `/` редиректит на `/static/index.html`.

```

  main.rs            точка входа: состояние, роутинг, авторизация запросов
  config.rs          config.toml + переменные окружения
  api/               HTTP API: auth, me, admin, library, playback, ytm
  auth.rs            пользователи, сессии, пароли, Subsonic-авторизация
  invites.rs         коды приглашений и регистрация
  db.rs              SQLite, миграции
  scanner/           сканирование, теги, CUE, watcher
  subsonic/          Subsonic API (JSON + XML)
  streaming/         Range-стриминг, CUE через ffmpeg
  lyrics.rs          .lrc/.txt + LRCLIB + lyrics.ovh
  scrobble.rs        история, Last.fm, ListenBrainz, метаданные YTM-треков
  live.rs            Live-очередь, миксы, статистика
  ytm/               cookies, InnerTube, yt-dlp, прокси и кэш
rustream-ui/
  src/main.js        SPA: маршруты, виды, плеер-бар, профиль, YTM
  src/player.js      Audio + Web Audio эквалайзер
  src/api.js         Subsonic- и /api-клиент
  src/style.css      Liquid Glass, тёмная тема, 5 палитр + свой цвет

deploy/              deploy.sh, .env.example, rustream.service
```

## Ограничения

- YouTube Music требует `yt-dlp` на сервере и валидные cookies профиля. Ссылки
  на аудио привязаны к IP сервера, поэтому сервер сам разрешает поток и проксирует
  его частями (Range); прямые ссылки клиентам не отдаются.
- Транскодирование не выполняется: сервер отдаёт исходный файл как есть.
- CUE-образы с несколькими `FILE` считаются трек-листом и не создают виртуальные
  треки; сами файлы сканируются отдельно.
- Свободной регистрации нет: только по приглашению или через администратора.

## Tauri

Веб-интерфейс не зависит от серверного рендеринга и использует только HTTP API,
поэтому его можно завернуть в Tauri: указать `devUrl`/`frontendDist` на эту сборку
и разрешить сетевые запросы к серверу. Это отдельный шаг — сами бинарники
Linux/Windows/macOS/Android в репозиторий не входят.
